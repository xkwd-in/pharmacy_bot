## 一、产品定位（一句话版）

**面向中小型医院药房、社区药店和养老院的、基于机械臂视觉融合识别的智能药品分拣与库存联动系统。**

变体（按场景）：
- 医院版：处方分装 / 患者一日量分装 / 错发药复核
- 药店版：处方核对 + 库存联动 + 客户自助取药柜
- 养老院版：按床位日服药包分装
- 实验室版（拓展）：试剂 / 耗材分类分拣

## 三、核心技术创新点（最重要——这一节决定技术分）

### 创新点 1：双通道药品识别融合（DUAL-CHANNEL Identification Fusion）

**问题背景**：单一识别方式都有盲区——
- 条码：包装磨损、反光、被手指遮挡 → 失败
- OCR：手写处方、字体特殊、包装弯曲 → 失败
- 视觉模型：未训练过的新药 → 失败

**我们的方案**：三路并行，先后兜底
```
摄像头一帧 → ┌── pyzbar 条码扫描（首选，确定性高）
            ├── PaddleOCR 文本识别（兜底 1）
            └── 自训练 YOLO 模型（兜底 2，识别包装形状）
            ↓
         任一路成功即可，三路均失败 → 人工复核报警
```

**差异化数据点（可在 BP 写）**：
- 单条码扫描方案盲区 ~15%（包装问题导致漏检）
- 单 OCR 方案盲区 ~25%（中英文混排、手写差异）
- 三路融合后理论盲区 < 1%（需做实验证）

**集成代码位置**（事实，可向评委展示真实代码）：
- 原始代码：`color_sorting.py` L252 `image_callback()`
- 创新点插入位置：L276 ROI 裁剪之后、颜色识别之前
- 增量代码量：约 30 行（pyzbar 调用 + 数据库查询 + 兜底分支）

### 创新点 2：四模式动态分拣调度

现有套件只能做"按颜色固定分类"，我们扩展为**四种业务模式可在运行时切换**：

| 模式 | 输入 | 输出 | 应用场景 |
|---|---|---|---|
| 品类分装 | 药品 SKU | 固定品类格 | 库存盘点、入库 |
| 处方分装 | 处方 JSON（多药混合）| 每患者一袋 | 门诊药房高峰 |
| 患者分装 | 患者 ID + 一日量 | 每患者按时段分包 | 住院药房 / 养老院 |
| 库存补货 | 库存阈值告警 | 缺货品类回补 | 夜间无人值守 |

**实现方式**：ROS 参数 `~mode` 启动时切换，运行时通过 ROS service `/sortting/set_mode` 改变。**这是评委爱听的"软件定义生产线"。**

### 创新点 3：HIS / 处方系统对接

**现状**：现有套件零业务对接能力。
**我们做**：
- FastAPI + HL7v2 / FHIR R4 接口标准（医院信息化国标）
- 自动从医院 HIS 拉取待分装处方
- 分装完成回写状态到 HIS 完成审计闭环

**这是医院真正会买单的能力**——单纯一台机械臂只是玩具，能对接 HIS 才是生产工具。

### 创新点 4（语音方向，加分项）

复用套件离线语音（科大讯飞 xf_mic_asr_offline，5 套现成 launch 模板）：
- 药剂师语音指令免接触操作（戴手套 / 无菌环境刚需）
- "分张三的处方"、"补 50 盒阿司匹林到 A3 格"
- 拓展开发量小（改词表 + 业务回调，~200 行）

| 层级 | 技术 | 来源 | 我们的工作 |

## 六、专利与知识产权布局建议

可申报方向（建议团队报 2-3 项，互联网+ 加分）：
1. **发明专利**：基于多通道视觉融合的药品识别方法（条码 + OCR + DL 三路融合的判优逻辑）
2. **实用新型**：药品分拣机械臂的可重构格架（适配不同药盒尺寸）
3. **软件著作权**：药品分拣调度管理系统 V1.0（业务层代码整包）

**软著最容易出**（1-3 个月下证），**实用新型**次之（6-12 个月），**发明专利**慢但分量最重（18-24 个月，建议先递交申请就行，比赛阶段「已受理」就够用）。
